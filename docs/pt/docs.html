1. Convolução FFT

O TaraDSP usa a biblioteca PFFFT (Pretty Fast FFT) para convolução de alta velocidade. O processo funciona assim:

  1. O sinal de entrada e a resposta ao impulso são preenchidos com zeros até a próxima potência de 2 (mínimo 32 amostras para o alinhamento do PFFFT).
  2. Ambos os sinais são transformados para o domínio da frequência via FFT direta (pffft_transform com PFFFT_FORWARD).
  3. Os sinais no domínio da frequência são multiplicados (teorema da convolução) via pffft_zconvolve_accumulate.
  4. O resultado é transformado de volta para o domínio do tempo via FFT inversa (pffft_transform com PFFFT_BACKWARD).
  5. A saída é escalada por 1/N e normalizada para pico 1.0.
Por que PFFFT? O PFFFT é projetado especificamente para aplicações de áudio. Suporta FFT real (não apenas complexa), que é duas vezes mais rápida para sinais de áudio de valor real. Também lida com instruções SIMD (SSE, NEON) para velocidade adicional.
Importante: pffft_transform (formato interno) deve ser usado, NÃO pffft_transform_ordered (formato de exibição). A função zconvolve_accumulate espera o formato interno. Usar a função errada produz resultados de convolução incorretos.

2. Remostragem

O TaraDSP pode reamostrar áudio para uma taxa de amostragem diferente. A seleção do motor de reamostragem segue esta prioridade:

  1. SoX Resampler (libsoxr) — qualidade mais alta, usado quando disponível
  2. R8Brain — alta qualidade, usado quando disponível
  3. FinalCD — ferramenta externa, usada quando disponível
  4. Interpolação linear — fallback, sempre disponível

Quando a reamostragem é solicitada (opção -r na CLI, ou seletor de taxa de amostragem na GUI), tanto o sinal de entrada quanto a resposta ao impulso são reamostrados para a taxa alvo antes da convolução.

3. Dither de Masterização

Ao gerar áudio de 16 bits, o TaraDSP aplica dithering TPDF (Função de Densidade de Probabilidade Triangular) com realimentação de erro. Este processo:

  1. Adiciona uma pequena quantidade de ruído aleatório (2 LSB pico a pico) ao sinal.
  2. Quantiza para 16 bits.
  3. Calcula o erro de quantização.
  4. Realimenta o erro na próxima amostra (realimentação de erro).
Por que dither? Sem dithering, a quantização para 16 bits produz distorção harmônica em níveis baixos. O dithering TPDF converte essa distorção em um piso de ruído constante de baixo nível, que é muito menos audível e mais natural.

4. Conversão para Fase Mínima

Respostas ao impulso de fase linear têm pre-ringing simétrico, que pode soar não natural. A opção --min (CLI) ou a caixa "Fase mínima" (GUI) converte a saída convoluída para fase mínima, que tem:

  • Sem pre-ringing (energia apenas após o impulso principal)
  • Menor latência
  • Som mais natural para simulação de cabinet e reverb

O algoritmo de conversão:

  1. Calcular a FFT do sinal.
  2. Extrair o espectro de magnitude.
  3. Calcular o log da magnitude.
  4. Calcular o cepstro real (FFT inversa do log da magnitude).
  5. Dobrar o cepstro para criar fase mínima.
  6. Calcular o espectro complexo (magnitude × fase mínima).
  7. FFT inversa para obter o sinal de fase mínima.

5. Fades e Corte

O TaraDSP pode aplicar fades e cortar o silêncio da resposta ao impulso antes da convolução:

  • Corte (-t / spin na GUI): Remove amostras abaixo de um limiar (em dB) do início e fim do IR. Útil para limpar respostas ao impulso com preenchimento de silêncio.
  • Fade (-f / spin na GUI): Aplica um fade-out da duração especificada (em ms) ao fim do IR. Um fade-in de 1ms é sempre aplicado para evitar cliques. Útil para suavizar os finais do IR.

8. Compilação a partir do Código-Fonte

Pré-requisitos

  • FreePascal Compiler (FPC) 3.2.2+ ou Lazarus IDE 3.0+
  • Lazarus/LCL para a GUI
  • Para uma compilação multiplataforma completa: compiladores cruzados do FPC (ppcrossx64, ppcrossa64, ppcrossarm) e Inno Setup 6
  • Python 3 (para tools/zip_app.py)
  • Zig (baixado automaticamente pelo build_all.bat para compilação cruzada de C no Linux)

Compilar tudo

./build_all.bat            # os 5 alvos + pacotes em Deploy/
./build_all.bat --check    # verificar apenas a cadeia de ferramentas

Compilar um único programa

# CLI
fpc -O2 -Fusrc -Sg -Sc TaraDSP.lpr

# GUI
lazbuild --build-all gui/TaraDSP_gui.lpi
