1. FFT Convolution

TaraDSP uses the PFFFT (Pretty Fast FFT) library for high-speed convolution. The process works as follows:

  1. The input signal and impulse response are zero-padded to the next power of 2 (minimum 32 samples for PFFFT alignment).
  2. Both signals are transformed to the frequency domain via forward FFT (pffft_transform with PFFFT_FORWARD).
  3. The frequency-domain signals are multiplied (convolution theorem) via pffft_zconvolve_accumulate.
  4. The result is transformed back to the time domain via inverse FFT (pffft_transform with PFFFT_BACKWARD).
  5. The output is scaled by 1/N and normalized to peak 1.0.
Why PFFFT? PFFFT is specifically designed for audio applications. It supports real FFT (not just complex), which is twice as fast for real-valued audio signals. It also handles SIMD instructions (SSE, NEON) for additional speed.
Important: pffft_transform (internal format) must be used, NOT pffft_transform_ordered (display format). The zconvolve_accumulate function expects internal format. Using the wrong function produces incorrect convolution results.

2. Resampling

TaraDSP can resample audio to a different sample rate. The resampling engine selection follows this priority:

  1. SoX Resampler (libsoxr) — highest quality, used when available
  2. R8Brain — high quality, used when available
  3. FinalCD — external tool, used when available
  4. Linear interpolation — fallback, always available

When resampling is requested (-r option in CLI, or sample rate selector in GUI), both the input signal and the impulse response are resampled to the target rate before convolution.

3. Mastering Dither

When outputting 16-bit audio, TaraDSP applies TPDF (Triangular Probability Density Function) dithering with error feedback. This process:

  1. Adds a small amount of random noise (2 LSB peak-to-peak) to the signal.
  2. Quantizes to 16-bit.
  3. Computes the quantization error.
  4. Feeds the error back into the next sample (error feedback).
Why dither? Without dithering, quantization to 16-bit produces harmonic distortion at low levels. TPDF dithering converts this distortion into a constant low-level noise floor, which is much less audible and more natural-sounding.

4. Minimum Phase Conversion

Linear-phase impulse responses have symmetric pre-ringing, which can sound unnatural. The --min option (CLI) or "Minimum phase" checkbox (GUI) converts the convolved output to minimum phase, which has:

  • No pre-ringing (energy only after the main impulse)
  • Lower latency
  • More natural sound for cabinet simulation and reverb

The conversion algorithm:

  1. Compute the FFT of the signal.
  2. Extract the magnitude spectrum.
  3. Compute the log magnitude.
  4. Compute the real cepstrum (inverse FFT of log magnitude).
  5. Fold the cepstrum to create minimum phase.
  6. Compute the complex spectrum (magnitude × minimum phase).
  7. Inverse FFT to get the minimum phase signal.

5. Fades and Trimming

TaraDSP can apply fades and trim silence from the impulse response before convolution:

  • Trim (-t / GUI spin): Removes samples below a threshold (in dB) from the start and end of the IR. Useful for cleaning up impulse responses with silence padding.
  • Fade (-f / GUI spin): Applies a fade-out of the specified duration (in ms) to the end of the IR. A 1ms fade-in is always applied to prevent clicks. Useful for smoothing IR endings.

8. Building from Source

Prerequisites

  • FreePascal Compiler (FPC) 3.2.2+ or Lazarus IDE 3.0+
  • Lazarus/LCL for the GUI
  • For a full multi-platform build: FPC cross-compilers (ppcrossx64, ppcrossa64, ppcrossarm) and Inno Setup 6
  • Python 3 (for tools/zip_app.py)
  • Zig (auto-downloaded by build_all.bat for Linux C cross-compilation)

Build everything

./build_all.bat            # all 5 targets + packages into Deploy/
./build_all.bat --check    # verify the toolchain only

Build a single program

# CLI
fpc -O2 -Fusrc -Sg -Sc TaraDSP.lpr

# GUI
lazbuild --build-all gui/TaraDSP_gui.lpi
