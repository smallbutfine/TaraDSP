1. Convolución FFT

TaraDSP usa la librería PFFFT (Pretty Fast FFT) para convolución de alta velocidad. El proceso funciona así:

  1. La señal de entrada y la respuesta al impulso se rellenan con ceros hasta la siguiente potencia de 2 (mínimo 32 muestras para la alineación de PFFFT).
  2. Ambas señales se transforman al dominio de la frecuencia mediante FFT directa (pffft_transform con PFFFT_FORWARD).
  3. Las señales en el dominio de la frecuencia se multiplican (teorema de convolución) mediante pffft_zconvolve_accumulate.
  4. El resultado se transforma de vuelta al dominio del tiempo mediante FFT inversa (pffft_transform con PFFFT_BACKWARD).
  5. La salida se escala por 1/N y se normaliza a un pico de 1.0.
¿Por qué PFFFT? PFFFT está diseñada específicamente para aplicaciones de audio. Soporta FFT real (no solo compleja), que es el doble de rápida para señales de audio de valor real. También maneja instrucciones SIMD (SSE, NEON) para velocidad adicional.
Importante: Se debe usar pffft_transform (formato interno), NO pffft_transform_ordered (formato de visualización). La función zconvolve_accumulate espera el formato interno. Usar la función incorrecta produce resultados de convolución incorrectos.

2. Remuestreo

TaraDSP puede remuestrear audio a una frecuencia de muestreo diferente. La selección del motor de remuestreo sigue esta prioridad:

  1. SoX Resampler (libsoxr) — la más alta calidad, usada cuando está disponible
  2. R8Brain — alta calidad, usada cuando está disponible
  3. FinalCD — herramienta externa, usada cuando está disponible
  4. Interpolación lineal — recurso, siempre disponible

Cuando se solicita remuestreo (opción -r en CLI, o selector de frecuencia de muestreo en GUI), tanto la señal de entrada como la respuesta al impulso se remuestrean a la frecuencia objetivo antes de la convolución.

3. Dither de Masterización

Al generar audio de 16 bits, TaraDSP aplica dithering TPDF (Función de Densidad de Probabilidad Triangular) con retroalimentación de error. Este proceso:

  1. Añade una pequeña cantidad de ruido aleatorio (2 LSB pico a pico) a la señal.
  2. Cuantiza a 16 bits.
  3. Calcula el error de cuantización.
  4. Retroalimenta el error a la siguiente muestra (retroalimentación de error).
¿Por qué dither? Sin dithering, la cuantización a 16 bits produce distorsión armónica a niveles bajos. El dithering TPDF convierte esta distorsión en un piso de ruido constante de bajo nivel, que es mucho menos audible y de sonido más natural.

4. Conversión a Fase Mínima

Las respuestas al impulso de fase lineal tienen pre-ringing simétrico, que puede sonar antinatural. La opción --min (CLI) o la casilla "Fase mínima" (GUI) convierte la salida convolucionada a fase mínima, que tiene:

  • Sin pre-ringing (energía solo después del impulso principal)
  • Menor latencia
  • Sonido más natural para simulación de cabinet y reverb

El algoritmo de conversión:

  1. Calcular la FFT de la señal.
  2. Extraer el espectro de magnitud.
  3. Calcular el logaritmo de la magnitud.
  4. Calcular el cepstrum real (FFT inversa del logaritmo de la magnitud).
  5. Plegar el cepstrum para crear fase mínima.
  6. Calcular el espectro complejo (magnitud × fase mínima).
  7. FFT inversa para obtener la señal de fase mínima.

5. Fundidos y Recorte

TaraDSP puede aplicar fundidos y recortar el silencio de la respuesta al impulso antes de la convolución:

  • Recortar (-t / spin en GUI): Elimina muestras por debajo de un umbral (en dB) del inicio y final de la IR. Útil para limpiar respuestas al impulso con relleno de silencio.
  • Fundido (-f / spin en GUI): Aplica un fundido de salida de la duración especificada (en ms) al final de la IR. Siempre se aplica un fundido de entrada de 1ms para prevenir clics. Útil para suavizar los finales de la IR.

8. Compilación desde el Código Fuente

Requisitos previos

  • FreePascal Compiler (FPC) 3.2.2+ o Lazarus IDE 3.0+
  • Lazarus/LCL para la GUI
  • Para una compilación multiplataforma completa: compiladores cruzados de FPC (ppcrossx64, ppcrossa64, ppcrossarm) e Inno Setup 6
  • Python 3 (para tools/zip_app.py)
  • Zig (descargado automáticamente por build_all.bat para la compilación cruzada de C en Linux)

Compilar todo

./build_all.bat            # los 5 objetivos + paquetes en Deploy/
./build_all.bat --check    # verificar solo la cadena de herramientas

Compilar un solo programa

# CLI
fpc -O2 -Fusrc -Sg -Sc TaraDSP.lpr

# GUI
lazbuild --build-all gui/TaraDSP_gui.lpi
```
