1. FFT-Faltung

TaraDSP verwendet die PFFFT-Bibliothek (Pretty Fast FFT) für Hochgeschwindigkeits-Faltung. Der Prozess funktioniert wie folgt:

  1. Das Eingangssignal und die Impulsantwort werden auf die nächste Zweierpotenz mit Nullen aufgefüllt (mindestens 32 Samples für PFFFT-Ausrichtung).
  2. Beide Signale werden über Vorwärts-FFT in den Frequenzbereich transformiert (pffft_transform mit PFFFT_FORWARD).
  3. Die Frequenzbereichssignale werden multipliziert (Faltungssatz) über pffft_zconvolve_accumulate.
  4. Das Ergebnis wird über inverse FFT zurück in den Zeitbereich transformiert (pffft_transform mit PFFFT_BACKWARD).
  5. Die Ausgabe wird mit 1/N skaliert und auf Peak 1.0 normalisiert.
Warum PFFFT? PFFFT wurde speziell für Audio-Anwendungen entwickelt. Es unterstützt echte FFT (nicht nur komplex), was für reellwertige Audiosignale doppelt so schnell ist. Es verarbeitet auch SIMD-Instruktionen (SSE, NEON) für zusätzliche Geschwindigkeit.
Wichtig: pffft_transform (internes Format) muss verwendet werden, NICHT pffft_transform_ordered (Anzeigeformat). Die zconvolve_accumulate-Funktion erwartet das interne Format. Die Verwendung der falschen Funktion erzeugt falsche Faltungsergebnisse.

2. Resampling

TaraDSP kann Audio auf eine andere Samplerate resamplen. Die Auswahl der Resampling-Engine folgt dieser Priorität:

  1. SoX Resampler (libsoxr) — höchste Qualität, verwendet wenn verfügbar
  2. R8Brain — hohe Qualität, verwendet wenn verfügbar
  3. FinalCD — externes Tool, verwendet wenn verfügbar
  4. Lineare Interpolation — Fallback, immer verfügbar

Wenn Resampling angefordert wird (-r-Option in der CLI oder Samplerate-Auswahl in der GUI), werden sowohl das Eingangssignal als auch die Impulsantwort vor der Faltung auf die Zielrate resampelt.

3. Mastering-Dither

Bei der Ausgabe von 16-Bit-Audio wendet TaraDSP TPDF-Dithering (Triangular Probability Density Function) mit Fehlerrückführung an. Dieser Prozess:

  1. Fügt dem Signal eine kleine Menge Rauschen hinzu (2 LSB Spitze-Spitze).
  2. Quantisiert auf 16-Bit.
  3. Berechnet den Quantisierungsfehler.
  4. Gibt den Fehler in das nächste Sample zurück (Fehlerrückführung).
Warum Dithering? Ohne Dithering erzeugt die Quantisierung auf 16-Bit harmonische Verzerrungen bei niedrigen Pegeln. TPDF-Dithering wandelt diese Verzerrung in einen konstanten Pegelboden um, der viel weniger hörbar und natürlicher klingt.

4. Minimum-Phase-Konvertierung

Linearphasige Impulsantworten haben symmetrisches Pre-Ringing, das unnatürlich klingen kann. Die --min-Option (CLI) oder das "Minimum Phase"-Checkbox (GUI) konvertiert die gefaltete Ausgabe zu Minimum Phase, die:

  • Kein Pre-Ringing (Energie nur nach dem Hauptimpuls)
  • Niedrigere Latenz
  • Natürlicheren Klang für Boxensimulation und Hall

Der Konvertierungsalgorithmus:

  1. Berechne die FFT des Signals.
  2. Extrahiere das Magnitudenspektrum.
  3. Berechne den Logarithmus der Magnitude.
  4. Berechne das reelle Cepstrum (inverse FFT des Logarithmus der Magnitude).
  5. Falte das Cepstrum, um Minimum Phase zu erzeugen.
  6. Berechne das komplexe Spektrum (Magnitude × Minimum Phase).
  7. Inverse FFT, um das Minimum-Phase-Signal zu erhalten.

5. Fades und Kürzung

TaraDSP kann Fades anwenden und Stille aus der Impulsantwort vor der Faltung schneiden:

  • Kürzen (-t / GUI-Spin): Entfernt Samples unterhalb eines Schwellenwerts (in dB) vom Anfang und Ende der IR. Nützlich zum Bereinigen von Impulsantworten mit Stille-Padding.
  • Fade (-f / GUI-Spin): Wendet einen Fade-Out der angegebenen Dauer (in ms) auf das Ende der IR an. Ein 1ms Fade-In wird immer angewendet, um Klicks zu verhindern. Nützlich zum Glätten von IR-Enden.

8. Aus Quellcode bauen

Voraussetzungen

  • FreePascal Compiler (FPC) 3.2.2+ oder Lazarus IDE 3.0+
  • Lazarus/LCL für die GUI
  • Für einen vollständigen Multi-Plattform-Build: FPC-Cross-Compiler (ppcrossx64, ppcrossa64, ppcrossarm) und Inno Setup 6
  • Python 3 (für tools/zip_app.py)
  • Zig (automatisch von build_all.bat für Linux-C-Cross-Kompilierung heruntergeladen)

Alles bauen

./build_all.bat            # alle 5 Ziele + Pakete in Deploy/
./build_all.bat --check    # nur Toolchain überprüfen

Einzelnes Programm bauen

# CLI
fpc -O2 -Fusrc -Sg -Sc TaraDSP.lpr

# GUI
lazbuild --build-all gui/TaraDSP_gui.lpi
